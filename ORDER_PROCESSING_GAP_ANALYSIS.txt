5. SUMMARY OF GAPS - RANKED
================================================================================

P1  Technical requirements do not reach procurement.
    Explicitly stated requirement. Non-compliant material can be purchased.
    Fix direction: carry OrderProcessingItem onto PRItem (and onward to
    RFQ / vendor PO), or at minimum render the requirement set on the PR
    and RFQ screens for the source Sales Order item.

P2  Delivery schedule is silently dropped.
    The column, the API and the display all exist; only the form is wired
    to the wrong field. The detail screen shows a permanently empty row.
    Smallest possible fix, currently misleading users.

P3  Quantity changes are not justified.
    Rate changes are audited to the RateRevision table and blocked without
    a remark; quantity changes have neither. Partial orders cannot be
    explained after the fact.

P4  No multi-item apply in Order Processing.
    Item-wise only. On multi-line orders sharing one inspection regime this
    is the single biggest source of user time and of data-entry error.

P5  No billing-address selection, and no client contact email / phone on
    the PO.

P6  Missing fields:
      - "Other test" free-text entry in the lab test list
      - "Additional spec the product must meet" at processing time
      - Client P.O. document (scanned copy) upload at registration

P7  "Order under NPIPE Inspection" is not modelled as an order-level
    option; it exists only as the per-item INHOUSE_QA value.

P8  Sl. No. / Item Code as per PO are entered twice (registration and
    processing) with no carry-forward between them.
